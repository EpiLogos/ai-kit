# Context and Knowledge Navigation

Semantic ref: `aikit:knowledge-navigation`. Native owner: `EpiLogos/ai-kit`.

## Procedure

1. Read the current Context as operative world + information horizon + focus; distinguish what is addressable from what is already loaded.
2. Inspect declared Context/knowledge sources, ProjectMap/code navigation and SemanticWiki/index surfaces available to the current Project/Profile.
3. Search/navigate progressively around the current Claim/question. Prefer source-owned refs and exact revisions; do not turn a retrieved projection into the canonical source.
4. Keep distinct projected forms reconcilable through their native refs/provenance rather than collapsing ownership because content is semantically related.
5. Bring only the evidence needed for the current act into the working horizon. Record sources used and unresolved gaps.
6. When a provider is absent/degraded, return that state honestly and use other eligible sources only if the effective context authorises them.

## Verification

Use AIKit knowledge-navigation/source-pool/wiki tests. Acceptance requires inspectable provider/source provenance and stable native refs across navigation/projection.
