# Meta-harness Craft

Semantic ref: `aikit:meta-harness-craft`. Native owner: `EpiLogos/ai-kit`.

Use this Skill when the quality of agent work depends on improving the world that prepares, situates, guides, checks or learns from repeated agent activity rather than only completing the immediate task.

A **meta-harness** is the deliberate, inspectable and revisable arrangement of persistent artifacts, context-selection rules, reusable praxis, validation and return paths through which an agent becomes situated enough to act coherently across sessions.

The term names a relation, not a new runtime subsystem. A narrow harness adapts a model to an execution environment. Meta-harness craft works on the larger operative field around that harness.

```text
persistent Project / human world
        ↓
addressable sources + authored artifacts + maintained knowledge
        ↓
Focus + retrieval / selection policy
        ↓
ContextResolution / bounded context packet
        ↓
Skills + Methods + Actions + harness
        ↓
action / development / encounter
        ↓
validation + evidence + write-back + history
        ↓
revised knowledge / praxis / authored proposal
```

The craft is successful when a fresh authorised agent can enter with a small seed, recover the right wider world on demand, act with clear provenance and authority, and return enough evidence for the world to become better articulated after the work.

## Relation to other AIKit praxis

Compose rather than duplicate:

- `product-understanding` establishes what a product or Project means and what is real now through provenance-aware traversal.
- `knowledge-navigation` finds and relates the source material needed for the current act.
- `profile-skillset` composes the repertoire available for projection.
- `skill-authoring` turns genuinely reusable intelligent praxis into a maintained Skill.
- `verification` checks claims and implementations against governing evidence.
- Meta-harness Craft asks whether the **conditions around repeated agent work** can themselves be better shaped.

A single task may use this Skill after another Skill exposes recurring friction, drift, repeated explanation, repeated retrieval or a missing return relation.

## Context is an operative medium

Treat context as more than text placed before a model. Context includes the selected portion of a wider operative world that is made cognitively available for this act.

Keep four states distinct:

```text
available world
    everything the authorised actor could discover or retrieve

selected / projected world
    capabilities and sources chosen as relevant for this Project, Profile or Focus

active context
    material actually resolved into the current session / turn / Method

used evidence
    material actually relied upon for a conclusion or action
```

This distinction supports both economy and explainability. The wider world can remain rich while the immediate context stays small.

Prefer a **thin orientation seed plus a discoverable horizon**. A useful seed usually tells the agent enough to locate:

- Project / Agency / Focus identity;
- human-authored ground or recognised purpose where available;
- selected SkillSet and relevant Methods;
- available ContextSources and how to retrieve from them;
- current work / history pointers that genuinely bear on the act;
- authority and governance boundaries;
- expected validation, evidence and return path.

The seed is a map into the operative world, not a compressed copy of the whole world.

## Crafting durable artifacts

Markdown is often an excellent carrier because humans and agents can both read and author it; git can diff it; links and headings make it addressable; metadata can type it; validators can inspect it; and it remains portable across tools. These are relational advantages rather than a special status for the `.md` extension.

Choose the medium that preserves the needed relations. A useful durable artifact makes these properties intelligible:

```text
purpose
    why this artifact exists and what decision or activity it supports

role / type
    Ground, governance, design, contract, working note, evidence, history,
    maintained knowledge, praxis, index, generated projection, etc.

authority + provenance
    who/what authored or derived it and what questions it can answer

scope
    where it applies and where a more local or more authoritative source takes over

addressability
    stable ref/path/identity by which humans and agents can retrieve or cite it

relations
    links to the sources, implementation, evidence, Skills or other artifacts it depends on

state
    stable reference, current working material, generated view, historical record, candidate, etc.

update / return path
    what kind of returned reality should revise it and who recognises the revision

validation
    checks that can detect structural, semantic or status drift where useful
```

A filename can help discovery; actual role and provenance determine meaning.

### Markdown craft as engineering

When a markdown artifact is part of an agentic operating system, spend design effort on the relations it carries. Ask:

1. What human or agent act should this make easier or more coherent?
2. What source authority does it carry, and what authority does it inherit from elsewhere?
3. What should be stable here, and what belongs in working/history/evidence material?
4. What minimum structure makes retrieval and navigation reliable?
5. What metadata or semantic refs make the artifact addressable without making prose mechanical?
6. What other artifact should own facts this document currently duplicates?
7. What validator or test could reveal drift worth acting on?
8. How does changed implementation or encounter reality return to this artifact?

Good context artifacts let the agent reconstruct relations instead of memorising slogans.

## The meta-harness reflex

During ordinary work, notice patterns that deserve a durable improvement. The aim is to make successful intelligence increasingly available to future humans and agents.

Use this mapping as a diagnostic, then verify the native owner before proposing a change:

```text
recurring orientation or relation
    → Guidance

recurring organised intelligent praxis
    → Skill

context-specific composition of Skills + Actions + ContextSources around a purpose
    → Method

Project/profile-specific adjustment to an unchanged Skill
    → UsageOverlay

repeated source lookup or recurring missing information horizon
    → ContextSource / index / knowledge-navigation improvement

repeated explanation of a stable Project fact or relation
    → appropriate durable source / maintained knowledge artifact

recurring vocabulary ambiguity
    → vocabulary / ontology / semantic-ref proposal at the owning layer

repeated state or contract drift
    → validator / verification rule / evidence relation

repeated session re-orientation
    → startup seed / ContextResolution / routing improvement

repeated outcome mismatch
    → Claim/Evidence return plus Method, Skill, design or authored-ground review

successful local pattern with broader value
    → reusable Skill/Method proposal with provenance
```

The classification is part of the craft. Similar-looking prose may belong to very different native objects because its role, authority and lifecycle differ.

## Forwarding an improvement

When the pattern is material, surface a compact **meta-harness improvement proposal** alongside the immediate result. Preserve human attention by making the reason and ownership legible.

Use this shape:

```text
Observed pattern
    what recurred or what friction/drift became visible

Why it matters
    effect on coherence, agency, human attention, provenance, evidence or repeatability

Proposed native object
    Guidance / Skill / Method / UsageOverlay / ContextSource / source artifact /
    validator / evidence-return relation / startup seed / other verified owner object

Native owner
    the product, Project or source authority that should carry it

Expected effect
    what becomes easier, clearer, more reliable or more agentically available

Evidence / provenance
    concrete sessions, artifacts, tests, returned observations or source relations

Recognition
    whether this is a routine maintained-object change or a consequential authored choice
    that should be brought to human Recognition
```

A proposal can be valuable even when implementation belongs elsewhere. Route it to the native owner with enough provenance for the owner to act.

## Situated agency check

Meta-harness craft works best when the agent can locate itself in the larger relation that makes its work possible.

Before changing the operative context, recover as needed:

```text
human / Project purpose
        ↓
authored ground + inherited social / technical world
        ↓
current Agency + harness + body + authority
        ↓
available Skills / Methods / Actions / ContextSources
        ↓
current Focus and selected context
        ↓
material action / encounter
        ↓
returned evidence and renewed world
```

The inherited world includes language, concepts, standards, institutions, codebases, tools, research, histories and practices accumulated by people beyond the immediate conversation. This matters operationally: a context artifact can point into that wider world with provenance rather than pretending every relevant relation must be recreated inside the prompt.

## First-mile, middle and return

For developmental work, preserve the whole authorship circuit:

```text
human authorship / Commission
        ↓
engineered operative context
        ↓
agent judgement + development
        ↓
material execution / encounter
        ↓
evidence + returned understanding
        ↓
human Recognition / renewed authorship where consequential
```

Meta-harness craft especially improves the middle without erasing either boundary. The human can invest attention in purpose, judgment, taste, alternatives and recognition while the operative world carries enough structure for agents to remain coherent across long or repeated work.

## Validation and drift

Where artifacts encode checkable relations, make validation executable. Useful checks include:

- required metadata or semantic refs are well-formed;
- linked source identities still resolve;
- generated projections can be traced to source;
- implementation assertions still match current code/tests where mechanically checkable;
- status artifacts agree with authoritative current state;
- repeated write-back/history follows the declared schema;
- a Method still resolves the Skills, Actions and ContextSources it claims to compose.

Validation should expose returned reality. The repair target remains the artifact or owner whose claim was falsified.

## Completion check

Before closing a meta-harness task, ask:

- Can a fresh authorised agent orient with a small seed and discover the wider context it needs?
- Are durable artifacts typed by role, provenance, scope and lifecycle clearly enough for human and agent use?
- Is the context horizon addressable rather than copied wholesale into prompts?
- Are Guidance, Skills, Methods, UsageOverlays, ContextSources and source artifacts being used for their distinct roles?
- Is repeated work becoming reusable praxis or better maintained knowledge where that would genuinely help?
- Can important drift be validated or evidenced?
- Does action return evidence/history to the world it changed?
- Have durable improvement proposals been routed to the actual native owner with their reason and provenance intact?
- Do consequential authored changes arrive at human Recognition rather than being smuggled in as implementation detail?

The goal is a living operative world in which human purpose, agent capability, structured context and returned reality can continuously become more mutually intelligible.
