# Models, harnesses and SessionSpace

Semantic ref: `aikit:runtime-operation`. Native owner: `EpiLogos/ai-kit`.

## Procedure

1. Inspect the current task/Profile/Agency demand and the eligible model roster rather than assuming a favourite model is available.
2. Compare capability/modalities, harness compatibility, role/task/SkillSet fitness, observed evidence, cost/latency/reliability/context characteristics and material requirements. Preserve the reason for preference.
3. Resolve harness composition independently from model identity. A model may be eligible while a required harness/component/provider is unavailable.
4. Inspect or create/resume SessionSpace and AgentSession through their canonical application services. SessionSpace is an AIKit-owned working environment, not Factory Run authority or Actuation Agency identity.
5. Materialise only Components/Surfaces whose provider and authority gates pass. Capability availability is not process-execution authority.
6. Preserve execution/session refs, source/provider revisions and any withheld/degraded reason in handoff evidence.

## Verification

Use model-roster, composition, SessionSpace contribution/lifecycle and provider-authority tests. Required provider execution must fail closed when the real activation authority is absent.
