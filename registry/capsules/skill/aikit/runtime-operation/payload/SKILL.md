# Models, harnesses and SessionSpace

Semantic ref: `aikit:runtime-operation`. Capsule identity remains
`skill/aikit/runtime-operation`, kind `skill`, in the existing operator set.
`METHOD:` classifies the description; it creates no second resource or grant.

## Intent and inputs

Help the person enter or resume the intended work with intelligible context,
actual agency and a usable response. Recover the request, World/root or child
Project, selected participant, source basis, existing authority, desired result
and Return destination. Read the governing UX/Wayfinder when the whole experience
is the task; a routine invocation needs only its relevant native procedure.

Central is the root meta-Project. An existing Agent can participate without a
Central Profile where admissible World evidence exists. A Profile supplies
residence/configuration, not Agent existence. Visibility does not authorise use.

## Procedure

1. **Orient and discover.** Resolve current subject, participant and permitted
   sources through native operations. Inspect the actual tool/Action description,
   input, result and failure contract from the selected version. A missing or
   unreadable owner is not an empty successful field; never invent a CLI flag.
2. **Resolve practice and context.** Discover applicable Skills/METHODs by their
   descriptions and sources. Inspect effective trust/target/selection, then actual
   projection and harness entry. Distinguish catalogued, selected, projected,
   linked, loaded and used. Required identity/governance and explicit selections
   reach the acting context; unrelated private material does not.
3. **Resolve the arrangement.** Inspect task/Profile/Agency demand and eligible
   Model routes. Preserve model identity, provider-native variants, explicit pins,
   credential state, modalities/compatibility, budget and policy. Keep required
   versus preferred harness/environment/material conditions and explain permitted
   fallback. Missing eligibility is not `true`, and a role label is not authority.
4. **Bind the actual work.** Use the existing session/Agency/WorldBinding operations.
   SessionSpace is not WorldBinding or Factory Run. Obtain Central's actual NOW
   destination where task work requires it. For Candidate work retain the intended
   source/worktree/cwd/test basis, allowed writes and Return route. Observe actual
   Workcell preparation and enforcement coverage, not merely a plan or hook file.
5. **Act through the real caller.** Send the authorised selected material through
   the supported session/gateway path and read its actual response. Validate native
   schema, identities, source/authority and outcome. Exit zero, arbitrary JSON,
   transport ACK or an instantiation record is not task completion. Record the
   request, recipient, context basis and causal delivery/response refs.
6. **Handle refusal and failure.** Explain the first failed relation and what
   remains usable. Missing credentials, unavailable providers, denied scope and
   unsupported continuation have distinct exits. Revalidate changed source and
   grants at effects. Do not widen scope or replay an uncertain consequential
   request to obtain success. Preserve cancelled, failed and late returns.
7. **Continue accurately.** Distinguish recorded conversation, prepared operative
   context and provider continuation. Use native resume/load when supported;
   otherwise disclose authorised rehydration or a new attempt. Closing/opening a
   Surface is not cancellation/new execution. Restore pending tools, permissions,
   requests and evidence across a committed context cursor; no hidden-reasoning
   capture or fake universal compaction control.
8. **Return.** Retain execution/session refs, actual source/provider/material
   revisions, exclusions and unresolved conditions. Give the person the result,
   what remains, what needs them and where evidence lives. Route human document
   contributions through Central receiving/review; never overwrite a human draft.

## Existing boundaries and bootstrap

Use #274/#275/#276/#277 for the current native runtime/dispatch/recurrence/guard
obligations. Source absence, withheld policy and a not-yet-published operation
remain explicit. During authorised implementation, fix the native owner or its
consumer; do not replace it with a production fixture. No personal installation
or commercial-model response is needed to write that code and controlled tests.

#299 tracks newly enabled Skills whose harness-root entry is missing. Verify
that boundary before claiming practice is available. A pointer update proves
filesystem resolution, not that an already-running Agent reread instructions.
An exact authorised body can be explicitly loaded as a bounded bootstrap input,
with source/reason recorded; that is not automated discovery or native install.

## Verification

Use existing model-roster, session, provider-authority and CAW public-operation
suites. Exercise root/child and profile-less participation, actual selected
context delivery, refusal, wrong source/worktree, duplicate/uncertain response,
interruption and supported continuation. Include a fresh Agent choosing this
procedure from its description, a newly enabled Skill and a changed existing
Skill. Verify real provider activation separately from fixture correctness.

The person validates whether the explanation and resumed work are intelligible.
Independent whole-feature verification follows the original UX acceptance, not
only this Method's implementation checks. Publication alone claims no loaded
harness, installed World or completed human experience.
