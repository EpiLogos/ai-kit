# Component, Surface and working-environment authoring

Semantic ref: `aikit:component-surface-authoring`. Native owner: `EpiLogos/ai-kit`.

## Procedure

1. Define the working-environment need and choose the existing Component/Surface/SessionSpace contribution contract rather than adding a UI-private configuration path.
2. Declare stable identity, provider/source provenance, target/surface semantics and eligibility requirements. Keep presentation separate from the semantic application operation.
3. Stage the contribution and inspect the resulting SessionSpace view before activation.
4. Pass trust/policy/platform/target and real provider-process authority gates. A visible Surface or available Component must not imply activation authority.
5. Prove lifecycle behaviour: contribution/discovery, preview/resolution, activation when authorised, withholding when unauthorised, and removal/reconciliation.
6. Verify the same semantic object can be consumed from supported human/agent surfaces without duplicating its domain meaning.

## Representative specimens

Use `session_space_contribution` and surfacing/provider-authority tests as the executable pattern. The accepted provider containment seam is the authority boundary; do not bypass it from a TUI/desktop adapter.
