## 0. What this receipt proves

This receipt does not replace the native owner tests with one synthetic mega-fixture. It composes the real owner seams which together constitute the AIKit-owned median Project vertical:

```text
physical ProjectCentral/native source specimen
        ↓
recognised human Ground + canonical Agent Wiki + retained native source
        ↓
bounded local source discovery / classification
        ↓
SemanticWiki / ProjectMap reflection
        ↓
real GitNexus CodeIndexProvider -> exact CodeReference
        ↓
bidirectional meaning ↔ description ↔ code ↔ verification
        ↓
Method + UsageOverlay receipts + ContextResolution
        ↓
Claude + Codex target-native Effective Skill projection
        ↓
AIKit Explain / History attribution
        ↓
application / harness / Actuation-owned embodied act and Return boundary
```

The physical Project/world, semantic source, code-index provider, target adapters and downstream act remain differentiated. The acceptance is stronger because each layer is proved through the implementation that actually owns it.

This is evidence of the **praxis input condition**, not a Run or a fitness judgement. Downstream owner-produced use/Return evidence is appended rather than synthesized into an AIKit Run ontology.

## 10. The embodied act boundary

The original acceptance target includes:

```text
real Agent act through Skills + ContextSources + Actions
        ↓
verification / evidence / Return
```

AIKit does **not** own a universal Action executor. Its core contextual Action search explicitly states that it is navigation search only and does not change stageability, trust, eligibility, subject or canonical Action identity. Method resolution likewise does not confer Action authority.

Therefore this PR proves the AIKit-owned condition immediately up to the act:

```text
source + Project meaning
    -> ContextSources / exact code / relevant Actions addressable
    -> Skill / UsageOverlay / Method condition
    -> ContextResolution
    -> target-native harness projection
    -> attributable Explain/History receipt
```

The actual embodied invocation and returned difference are owned by the application/harness and situated Actuation/Factory relation. A genuine physical Project/Agent run must be used for that final boundary; introducing a fake AIKit `execute Action` primitive solely to make this test monolithic would violate the architecture.

The same is true of the user's installed `~/Central/Work/*`: GitHub CI can prove the filesystem/provider contracts but cannot honestly substitute a committed fixture for the person's actual Project world.
