# Telos — ai-kit project register

The long horizon for this project, deliberately outside the daily field.
Placement per the integrated day/now/telos field spec
(Control/agents/now/flows/day-now-telos-integrated-field-spec-2026-09-17-1645.md):
the capability spec and the documents the operative field parses live here.

## What lives in this folder

- `capability-matrix.{json,csv,md}` — the project's capability spec
  (`ql-capability-matrix/1`): need/operation/outcome per capability,
  implementation status, accounts, and the seed×field relation records.
  This is the machine-read carrier for AIKit's matrix reading
  (`now-context prepare` matrix block) and for the Jev/Redis operative
  field assembly (`scripts/jev-redis/assemble_contemplation.py
  --projectcentral`, which discovers carriers here first).
- `aikit.html` — the whole-account carrier the matrix's account anchors
  (`aikit.html#q…`) resolve against.
- Root-register telos (the owner's long horizon, e.g. the submission cut
  and its tracks) remains at `Control/user/telos/`; this project folder
  holds the project's own spec documents and, when authored, its
  goal/track entries in the same `goal.md` + `tracks/` shape.

## Law

Distributed default per the ProjectCentral telos propagation: created
when missing, never read-compared or overwritten by tooling. Recognitions
returned from contemplation over these documents name the telos
goal/track they serve (chain of custody: telos → task → now → sessions).
